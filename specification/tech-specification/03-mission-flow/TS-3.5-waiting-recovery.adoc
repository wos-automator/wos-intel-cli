=== TS-3.5 Waiting and recovery

Implements <<FR-3.6>>.

* `_tap` / `_back`: log, send, `sleep(tap_delay)`.
* `_observe`: `_look` (fresh screenshot → `detect_state`; logs the state; writes
  `debug/<step>-<STATE>.png` when debugging). While the state is `HINT` – at most `max_back`
  times, never in a dry run – the `hint` match is tapped and `_look` repeated, so every caller
  sees the screen below the hint (<<US-5.1>>).
* `_expect(states, timeout=expect_timeout)`: observe; return on a wanted state; raise
  `StepFailed` once the deadline has passed; otherwise `sleep(poll_interval)` and repeat.
* `_recover`: up to `max_back` times: observe; stop on `INTEL*` or `WORLD`; `REWARDS` → tap the
  rewards exit; `VICTORY`/`DEFEAT` → tap the exit text; anything else → BACK.

* `_save_failure`: on `MissionRejected` and `StepFailed` the last observed screenshot is written
  unannotated to `debug/failure-<step>-<STATE>.png` (`failure_dir`, always set by the CLI), so
  that an unknown dialog can be turned into a reference.

`sleep`, `clock` and `now` are injected, so the tests run without real waiting.

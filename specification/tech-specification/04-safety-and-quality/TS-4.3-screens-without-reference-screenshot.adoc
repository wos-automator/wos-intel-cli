=== TS-4.3 Screens without reference screenshot

Implements <<NFR-3>>.

[cols="1,2,2"]
|===
|Screen |Current handling |To complete

|Rescue popup |green button by hue (<<TS-2.4>>) |`snap`, cut `templates/btn_rescue.png`
|After the expert tap |re-evaluate the screen; anything but `INTEL*` → recovery (<<TS-3.1>>) |`snap` what appears, extend the flow if it needs a confirmation
|Rescue dialog pin |scaled `tent_mask` (<<TS-2.4>>) |verify on the device
|`DEFEAT` |exit text without "Victory!" (<<TS-2.1>>) |verify on the device
|Not enough stamina |`templates/dialog_no_stamina.png` if present; else timeout → recovery |`snap`, cut the template

|===

The optional templates (`btn_rescue`, `dialog_no_stamina`, `dialog_no_troops`) are loaded when
their file exists and otherwise never match (`Detector`, <<TS-2.1>>).

Synthetic test screens (`tests/conftest.py`) stand in for the missing references: a recoloured
Explore button for Rescue, a dialog with a pasted tent/skull mask, a victory screen without
title, a Deploy screen without the prevail hint. They are used by `test_states` (`defeat`),
`test_action_button` (`rescue-popup`), `test_dialog_type` (`rescue-dialog`) and
`test_likely_to_prevail` (`deploy-unlikely`) in `tests/test_detect.py`, and by
`test_rescue_starts_without_deploy`, `test_lost_fight_is_dismissed_and_the_run_continues` and
`test_hunt_without_prevail_hint_is_not_deployed` in `tests/test_flow.py`;
`test_optional_template_never_matches_while_missing` checks the optional templates.

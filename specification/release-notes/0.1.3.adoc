== Release v0.1.3 (unreleased)

Built with agent-skills v0.6.1.

=== Features

* Requirements-based blackbox tests: the acceptance scenarios in `specification/acceptance/`
  accept <<FR-1.3>> and <<FR-1.4>>; every release carries a test report and a traceability
  report (<<TS-4.2>>, <<US-1.2>>).

=== Documentation

* Architecture overview `architecture-web.adoc` in the structure of arc42: context, solution
  strategy with the logical functions (<<LF-1>> to <<LF-10>>) and their principles, building
  blocks with the allocation of the functions to the modules, cross-cutting concepts, decisions (<<ADR-1>>, <<ADR-2>>,
  <<ADR-3>>) and glossary. The project structure is part of its building block view instead
  of <<NFR-1>> and the chapter intro of the technical specification.
* The detection requirements describe behaviour only: the method is in the technical
  specification, the values are the defaults of `config.toml`, and the expected results on the
  reference screenshots are acceptance scenarios (<<FR-2.1>>, <<FR-2.2>>, <<FR-2.3>>,
  <<FR-2.4>>, <<FR-2.5>>, <<FR-2.6>>, <<FR-2.7>>).
* The mission flow requirements keep the values the operator experiences (mission costs,
  minimum stamina, how long a run waits); the values that only tune a step (delays, screenshot
  intervals, step timeouts, tap positions, distances) are in the technical specification and
  `config.toml` (<<FR-3.2>>, <<FR-3.3>>, <<FR-3.4>>,
  <<FR-3.5>>, <<FR-3.6>>, <<FR-3.7>>,
  <<FR-3.8>>, <<FR-3.9>>).
* The platform, safety and event requirements follow the same split (<<FR-1.1>>, <<FR-4.1>>, <<NFR-2>>,
  <<NFR-3>>, <<FR-5.1>>, <<FR-5.2>>,
  <<FR-5.3>>).
* The data model of the detection lists the states `HINT`, `QUIT_CONFIRMATION` and
  `SESSION_LOST` of 0.1.1 (<<FR-2.1>>).
* The run loop names the parameter `failure_dir` and the outcomes `REWARDS_HELD` and
  `EVENT_UNREADABLE` of 0.1.1 (<<TS-3.1>>).

* The specification validator is pinned in `.agents/spec-validator.lock` (spec-validator
  0.2.1) instead of inside the agent-skills library (<<TS-4.2>>).

== 0.1.1 (unreleased)

=== Features

* Busy march queues (BUG-0014): the counter "Marching N/M" on the world map is read with the
  digit OCR. While all march queues are busy, hunt and boss targets are deferred: combat and
  rescue missions go on, a hunt or boss whose popup does not open is neither tapped again nor
  counted as a failure, and with only hunt and boss left the run tries again every 60 s. If the
  queues stay busy for 15 min the run ends regularly with "all march queues busy". New settings
  `queue_poll` and `queue_timeout` in `[timing]` and `march_region` in `[ocr]` (<<US-3.8>>,
  <<FR-2.7>>, <<FR-3.9>>).

* Flame and Fangs event: the event icon on the Intel screen and its countdown "Opens in
  HH:MM:SS" are detected; the run logs when the event starts. New template `event_icon`, new
  settings `countdown_region`, `countdown_lo` and `countdown_hi` in `[ocr]` (<<US-6.1>>,
  <<FR-5.1>>).
* The expiry "Intel Expires In HH:MM:SS" of the mission dialogs is read with digit templates
  for the dark text, cut from the dialog references. New settings `expiry_region`, `dark_lo`
  and `dark_hi` in `[ocr]` (<<US-6.2>>, <<FR-5.2>>).
* Pre-event rules of the Flame and Fangs event: while the event icon counts down, each
  mission's expiry is compared with the event start. Missions that expire before it are
  finished and claimed first; then the run stores a hold in `state.json`, finishes the missions
  that expire with the event start and claims nothing until the event, also in later runs.
  Missions that expire after the start are left for the event. The run ends with "rewards held
  for the event"; an unreadable countdown ends it untouched. New section `[event]` with
  `tolerance_minutes` (<<US-6.3>>, <<FR-5.3>>).
* Before the Flame and Fangs event the expert is only used within 2 h of the start, so its
  missions are still available during the event. New setting `expert_hours` in `[event]`
  (<<US-6.4>>, <<FR-5.4>>).

=== Fixes

* BUG-0002: the hint bubble "You have enabled Simple Battle Mode …" over the world map is
  recognised as the new state `HINT` and tapped away; the running step continues. Before, the
  screen was `UNKNOWN` and the recovery pressed BACK on it (<<US-5.1>>, <<FR-2.1>>, <<FR-3.6>>).
* BUG-0006: the "Quit game?" confirmation that a BACK on a screen with nothing open brings up
  is recognised as `QUIT_CONFIRMATION`; the recovery taps "Cancel" and presses no further BACK
  (<<US-5.2>>, <<FR-3.6>>, <<FR-4.1>>).
* BUG-0028 (also BUG-0095b, BUG-0141): when the popup of the world target does not open after
  "View", the intel pin above the target is detected and the target is tapped once more,
  only if the pin shows the expected mission type. New settings `world_pin_*` in `[symbols]`
  (<<US-5.3>>, <<FR-2.6>>, <<FR-3.4>>).
* BUG-0098: the retry also applies to the boss; its skull pin is recognised on the world map,
  and the boss is locked for the refresh cycle only after it has been deployed (<<US-5.5>>,
  <<FR-3.5>>).
* BUG-0118: a target that is no longer on the world map after "View" (no popup, no pin of
  its type) is skipped for the run without counting as a failure; the run returns to the Intel
  screen and selects the next mission. Before, three such targets in a row ended the run
  (<<US-5.6>>, <<FR-3.4>>).
* BUG-0095a: the dialog "The account has been logged in on another device." is recognised as
  `SESSION_LOST`. The run waits 60 s, taps "Reconnect", waits up to 120 s for the Intel screen
  or the world map and starts over without counting a failure. New settings
  `reconnect_delay` and `reconnect_timeout` in `[timing]` (<<US-5.4>>, <<FR-3.6>>, <<FR-4.1>>).

=== Documentation

* `SPEC.md §3.7` describes the Flame and Fangs event and the pre-event rules: claim the
  missions that expire before the event, finish but do not claim those that expire with its
  start, ignore the rest. Specified in <<FR-5.1>> to <<FR-5.4>>, <<TS-5.1>>, <<TS-5.2>> and
  <<US-6.1>> to <<US-6.4>>. The firebeast pin of the event itself is not covered yet.

* `SPEC.md §5` states what the run has to do when all march queues are busy: work only on
  targets that are neither hunt nor boss (BUG-0014).
* The specification moved from `docs/` to `specification/`, with one subdirectory per master
  file (`requirements/`, `tech-specification/`, `backlog/`, `release-notes/`) and
  `stakeholder/` for the chapters of `SPEC.md`. Each chapter is a folder whose `index.adoc`
  includes one file per requirement, technical specification or user story, so a single item
  can be read without its whole chapter. The rendered documents are unchanged (<<NFR-2>>).
* `SPEC.md` is now an index; its sections live in `specification/stakeholder/<NN>-<topic>.md`
  and keep their numbers, so references like `SPEC.md §3.5` stay valid.
* `scripts/validate_specs.py` follows nested includes relative to the including file and
  reports every item file that no master reaches (<<US-4.2>>, <<NFR-2>>).

=== Breaking changes

* Paths below `docs/specifications/`, `docs/tech-specifications/`, `docs/backlog/` and
  `docs/release-notes/` no longer exist.

== Cross-cutting Concepts

=== The `Device` protocol and the fake game

`flow.Device` is a `typing.Protocol` with `check`, `screenshot`, `tap` and `back`; `adb.Adb`
satisfies it structurally, as does the scripted fake game of the tests (<<TS-3.1>>,
<<TS-1.1>>). Together with the injected `sleep`, `clock` and `now` this is the seam that
separates the run from the machine it runs on: `Runner` can be driven through a whole run on
reference screenshots, with a fake clock that advances only when the code sleeps
(<<TS-3.5>>, <<TS-4.2>>). The same four methods are also the complete input surface of the
program, which is what <<TS-4.1>> builds on.

=== Reference screenshots and templates

`ref/` holds screenshots of the device, taken with `snap`. They are at once the stakeholder's
evidence (SPEC.md §8 names the content of each), the oracle of the detection tests
(<<NFR-2>>) and the source of the templates: `tools/cut_templates.py` cuts the digit glyphs
and the derived templates from them, the symbol masks and button cut-outs are stored in
`templates/`. `Detector` loads all templates once; a required template that is missing is an
error, an optional one simply does not take part (<<TS-4.3>>). Every template is matched
with `TM_CCOEFF_NORMED` inside a configured region against a configured threshold. Used by
<<TS-2.1>>, <<TS-2.2>>, <<TS-2.3>>, <<TS-2.4>>, <<TS-5.1>> and <<TS-5.3>>. A new screen
therefore costs a reference, a cut and a test, never a code path that guesses (<<ADR-1>>).

=== Persistent run state

Two facts outlive a run: the boss was attacked in the current refresh cycle, and rewards are
held for the Flame and Fangs event. `state.StateStore` keeps both in `state.json`, written
atomically through a temporary file; a missing, unreadable or malformed file means "nothing
remembered", so a damaged file can never block a run (<<TS-3.4>>, <<TS-5.2>>). `flow` reads
the store on every evaluation of the Intel screen and writes it only after the game has
confirmed the step (boss deployed, claim phase finished).

=== Logging and debug images

Every observed state, every symbol, the stamina and every tap or BACK with its reason go to
stdout with a timestamp (<<TS-1.2>>). With `--debug` every analysed screenshot is written to
`debug/` with the matches and symbols drawn in by `Detector.annotate`; the screenshot on which
a step failed or a mission was skipped is always kept unannotated, so it can become the next
reference (<<TS-3.5>>, <<TS-2.4>>). The `detect` command writes the same annotated image for
a file. Since the device is not at hand when a run misbehaves, these images and the log are
the only evidence; several failure screenshots of device runs became reference screenshots
of release 0.1.1 (<<TS-3.6>>, <<TS-2.4>>).

=== Configuration: defaults in code, overrides in `config.toml`

Every threshold, region, wait time and cost is a field of a frozen dataclass in
`wos_intel/config.py`; the defaults are the values of SPEC.md, so `Config()` without a file
is the specified behaviour and is what the tests use (<<TS-1.3>>). `config.toml` overrides
single keys and is rejected on an unknown key or a wrong type. The modules receive the
sections they need (`Adb(config.device)`, `Detector(config)`, `Runner(config, ...)`), so a
value measured on the device can be tuned without a code change. `adb`, `detect` and `flow`
read it; `event` and `state` take no configuration.

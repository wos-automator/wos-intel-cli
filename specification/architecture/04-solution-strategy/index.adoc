== Solution Strategy

The program has no access to the game's data. It works the way a player does: look at the
screen, recognise what is shown, tap. Six ideas follow from that.

Screenshot-driven state machine::
Every decision starts with a fresh screenshot, classified as exactly one screen state
(<<FR-2.1>>, <<TS-2.1>>). The run loop and the mission sequences are transitions between these
states: tap, then poll with a timeout until the expected state shows up (<<TS-3.1>>,
<<TS-3.2>>, <<TS-3.5>>). Taps are never chained blindly (SPEC.md §2).

Detection as a pure function::
`wos_intel/detect.py` depends on the screenshot, the templates and the configuration only;
it knows neither the device nor the time nor the run (<<TS-2.1>> to <<TS-2.4>>). It can
therefore be run on a file (`detect`, <<FR-1.3>>) and tested against the reference
screenshots in `ref/` with the values the stakeholder measured (<<NFR-2>>, <<AT-1.1>>).

Safety by construction::
The device offers tap, BACK and screenshot, nothing else (<<TS-1.1>>, <<FR-4.2>>). Every tap
coordinate comes from the detection of the current screenshot; the one fixed point is
documented (<<FR-4.1>>, <<TS-4.1>>). An unknown screen is only ever left with BACK, so a
dialog the program does not know cannot be confirmed.

Minimal technology::
Runtime dependencies are OpenCV and numpy (<<NFR-1>>). Buttons, titles and mission symbols
are found by template matching, digits by matching single glyphs against digit templates; no
OCR engine, no server (<<FR-2.5>>, <<TS-2.3>>, <<ADR-1>>). The device is reached through the
`adb` binary, not through a library (<<ADR-2>>).

Testability by substitution::
The run loop sees the device through a protocol and receives sleep, clock and current time as
parameters (<<TS-3.1>>, <<TS-3.5>>). The component tests replace the game with a scripted
fake built from reference screenshots and run whole runs without waiting (<<TS-4.2>>,
<<ADR-3>>).

Completed from device evidence::
Screens without a reference screenshot are implemented against synthetic screens and
optional templates; `snap` records the missing reference, `tools/cut_templates.py` cuts the
template, and the path becomes active as soon as the file exists (<<NFR-3>>, <<TS-4.3>>).
The screenshot of every failed step is kept for the same purpose (<<FR-3.6>>).
